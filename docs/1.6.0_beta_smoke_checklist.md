# ProServe Hub 1.6.0 Beta Smoke Checklist

Use this checklist before uploading or widening the 1.6.0 beta in Play Console or TestFlight. Do not submit a store build until Windows/Android and Mac/iOS both validate the same Git commit.

## Release Target

- Version: `1.6.0+12`
- Shared branch: `codex/1.6.0-windows-build-sync`
- Firebase project: `proserve-hub-ada0e`
- Android package: `com.verohue.proservehub`
- Release posture: beta/internal testing only until both platforms pass smoke testing.

## Git Sync Gate

Run on both Windows and Mac:

```bash
git fetch origin
git checkout codex/1.6.0-windows-build-sync
git pull --ff-only origin codex/1.6.0-windows-build-sync
git log --oneline -3
git status --short
```

Pass criteria:

- Both machines are on the same latest commit.
- `git status --short` is clean before store builds.
- No platform-specific branch has unmerged release-critical fixes.

## Local Build Gate

Windows/Android:

```bash
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter build appbundle --release
```

Mac/iOS:

```bash
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter build ios --release --no-codesign
```

Pass criteria:

- Analyzer has no issues.
- Flutter tests pass.
- Android AAB builds successfully.
- iOS release build or archive path succeeds on Mac.

## Backend Gate

Before production/beta smoke tests:

```bash
cd functions && npm test
cd ..
firebase emulators:exec --only firestore "cd rules_tests && npm test"
node --check functions/index.js
```

Console checks:

- Firestore rules deployed from the same release commit.
- Functions secrets are present for Stripe, AI, and any production-only services.
- Stripe webhook URL points to the production Firebase Functions endpoint.
- App Check, Auth providers, FCM, and Crashlytics are configured for release builds.
- Android SHA fingerprints include debug, upload, and Play app signing certificates.

Pass criteria:

- Rules tests pass.
- Functions payment and entitlement tests pass without production credentials.
- Functions syntax check passes.
- No production console mismatch is found before uploading store builds.

## Android Play Internal Test

Play Console checks:

- Package name is `com.verohue.proservehub`.
- Version code is higher than the approved 1.5.0 build.
- App signing/upload certificate is accepted.
- Billing products/subscriptions match the app and backend verification.
- Data safety and permission declarations match actual app behavior.
- Internal testing upload installs successfully from Play.

Android device smoke:

- Install from Play internal testing, not only local sideload.
- Sign in as customer.
- Sign in as contractor.
- Test Android 13+ notification permission.
- Test camera/photo picker, location, microphone, Google Sign-In, billing restore/purchase path, `proservehub://` custom scheme, and `https://proservehub.app` app link fallback.

## iOS TestFlight Smoke

App Store Connect checks:

- Version/build is `1.6.0+12` or the agreed final build number.
- TestFlight build processes successfully.
- Privacy labels and subscription/IAP metadata still match the app.
- Review notes mention beta/internal testing status if needed.

iOS device smoke:

- Install from TestFlight.
- Sign in as customer.
- Sign in as contractor.
- Test notifications, photos/camera, location, microphone, Apple Sign-In, subscriptions, universal links, and TestFlight update path.

## Customer Flow Smoke

Customer account:

- Open app and confirm localized home/quick actions render in English.
- Switch to Spanish and confirm home, project, team, and Action Center labels do not clip.
- Create a job request with service, location, description, and photos.
- Confirm draft/resume behavior if the request is interrupted.
- View quote list and compare quote details.
- Accept a quote.
- Open Job Command Center.
- Open chat from the job.
- Confirm escrow/protected payment state is visible.
- Mark job complete or follow the completion path available in test data.
- Submit a review.

Pass criteria:

- Customer always sees a clear next step.
- No screen appears empty without explaining why.
- No English fallback appears in the primary Spanish customer path.

## Contractor Flow Smoke

Contractor account:

- Open contractor home and confirm profile, payout status, and quick actions render correctly.
- Browse lead/job feed.
- Unlock or open an available lead with test credits.
- Submit a quote.
- Open Job Command Center after winning/claiming a job.
- Open chat from the job.
- Create an invoice from job/estimate where available.
- Use pricing calculator and saved estimates.
- Confirm Tools Hub grouping, locked states, and Spanish labels.
- Confirm payout setup CTA is obvious when Stripe onboarding is incomplete.

Pass criteria:

- Contractor can move from lead to quote to job to invoice/payment without hidden routes.
- Pro/Enterprise locked states are clear.
- Primary contractor tools do not show hardcoded English in Spanish.

## Admin Flow Smoke

Admin account:

- Open admin overview.
- Check severity queues for escrows, disputes, payments, reports, and contractor verification.
- Open Payment Operations.
- Add an admin note to an escrow/payment/payout issue.
- Mark escrow/payment reviewed.
- Mark payout setup contacted.
- Confirm admin notes appear on refresh.
- Confirm payment status and amount cannot be changed from the client.

Pass criteria:

- Admin can diagnose stuck money or trust issues without going directly to Firebase Console first.
- Admin action history is visible and not writable by non-admin users.

## Payment/Stripe Smoke

Stripe test mode or controlled beta test:

- Subscription checkout and entitlement sync.
- Lead credit purchase and credit grant.
- Invoice payment link creation and payment status update.
- Escrow funding.
- Escrow release.
- Escrow refund.
- Failed payment state.
- Webhook retry or duplicate webhook idempotency.

Pass criteria:

- Every payment state is visible to the right user.
- Admin can see failed/stuck states.
- No paid feature is granted solely by UI state.

## Final Release Decision

Release to wider beta only when:

- Android internal test install passes.
- iOS TestFlight install passes.
- Customer, contractor, and admin smoke flows pass on real devices.
- Firestore rules and backend checks pass.
- Stripe test-mode flows pass.
- Spanish customer and contractor primary paths are acceptable on mobile width.
- Mac and Windows confirm the same release commit.

If any blocker is found, fix it on `codex/1.6.0-windows-build-sync`, rerun platform checks, and upload a new build number.
